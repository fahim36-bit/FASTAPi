Quick Start

Six small steps from zero to a running API.

1

Get the files

Download the zip (button above) or create this folder structure and paste each file from the Project Files section.

expense_tracker/
├── main.py
├── database.py
├── models.py
├── schemas.py
├── security.py
├── routers/
│   ├── __init__.py
│   ├── auth.py
│   └── transactions.py
├── tests/
│   └── test_transactions.py
├── requirements.txt
├── pytest.ini
├── .env.example
├── .gitignore
└── README.md
2

Install dependencies

Use a virtual environment (Python 3.10+).

cd expense_tracker
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
3

Configure the database

Create a .env file (copy .env.example). If DATABASE_URL is missing, the app falls back to a local SQLite file so you can still try it.

DATABASE_URL=postgresql://user:password@host:5432/dbname
SECRET_KEY=any-long-random-string
4

Run the server

Tables are created automatically on startup. Then open the interactive docs.

uvicorn main:app --reload
# → http://127.0.0.1:8000/docs
5

Run the tests

6 Pytest cases (create, get all, get one, update, delete, unauthorized). They use a local test.db, never your real database.

pytest -v
6

Push to GitHub & deploy on Render

Commit everything (except .env) and follow the Deploy section.

git init
git add .
git commit -m "Expense Tracker API"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/expense-tracker-api.git
git push -u origin main

How authentication works

Step 1
Register
POST /auth/register — password is hashed with bcrypt before saving.
Step 2
Login
POST /auth/login — returns access_token + token_type (JWT).
Step 3
Send the token
Header Authorization: Bearer <token>. In Swagger just click Authorize.
Step 4
Own data only
Every /transactions query is filtered by owner_id == current_user.id.

API Endpoints

    
All /transactions routes require a JWT (🔒). Filter route is declared before /{transaction_id} so "filter" is never read as an id.


    

      

        
MethodEndpointAuthWhat it doesMarks

        
          
POST/auth/register—Validate with Pydantic, hash password, save user, never return the hash10

          
POST/auth/login—Verify username & password, return access_token + token_type10

          
POST/transactions🔒Create; owner is the logged-in user; amount > 0, type ∈ income | expense10

          
GET/transactions🔒All transactions of the logged-in user only10

          
GET/transactions/{transaction_id}🔒One transaction; 404 if missing or owned by someone else10

          
PUT/transactions/{transaction_id}🔒Update own transaction; 404 with a clear message if not found10

          
DELETE/transactions/{transaction_id}🔒Delete; 200 + confirmation message, or 4045

          
GET/transactions/filter🔒Query params: type, category, minimum_amount, maximum_amount15

        
      

    


    

      

        
Example request body — create / update

        
{
  "title": "Lunch",
  "amount": 250,
  "type": "expense",
  "category": "Food",
  "date": "2025-01-15"
}

      

      

        
Example filter requests

        
GET /transactions/filter?type=expense&category=Food
GET /transactions/filter?minimum_amount=100&maximum_amount=5000
GET /transactions/filter?type=income

        
Every parameter is optional; combine any of them.

Validation rules (Pydantic)

      
    
        
  • amount must be > 0 → Field(gt=0)
    • 
        
  • type must be "income" or "expense" → Literal[...]
    • 
        
  • email must be a valid email → EmailStr
    • 
        
  • password 6–72 characters (bcrypt limit) → Field(min_length=6, max_length=72)
    • 
        
  • Response models never include hashed_password
    • 
        
  • Invalid input returns 422 automatically — the app never crashes
